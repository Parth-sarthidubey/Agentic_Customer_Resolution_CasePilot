One case, end to end

A customer message enters on the left with no order number. A verified state change leaves on the right — or a human is asked, or the agent refuses. Every box below is code in the repository, not an intention.

The loop that makes it agentic

Refusal is evidence

An action the enterprise rejects re-enters planning as a new fact. A plan repeating an action already refused with identical parameters is blocked before execution.

Done is proven

A case closes only when SQL against the systems of record matches the plan's promised outcome. The agent does not get to assert success.

Limits are code

Approval thresholds live in Python, never in a prompt, so no message from a customer can widen them.

Bounded by MAX_AGENT_STEPS, MAX_AUDIT_ROUNDS = 2 and MAX_REPLANS = 3; when the budget is spent the case escalates carrying everything it learned, so a human never restarts from zero.
